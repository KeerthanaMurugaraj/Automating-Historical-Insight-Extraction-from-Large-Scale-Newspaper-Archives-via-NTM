Code and worked example

Automating Historical Insight Extraction from Large-Scale Newspaper Archives using BERTopic

A pipeline for finding themes in historical newspaper archives and following them over time, with a comparison against classical topic models.

View the code on GitHub See the example Use it on your own data

What this project does

Historical newspaper archives are hard to analyse at scale. Topics shift over decades, OCR introduces noise, and the volume of text rules out manual reading. This project applies BERTopic, an embedding-based topic-modeling approach, to extract coherent themes from such archives and to trace how they change over time.

The repository accompanies a paper submitted to Digital Scholarship in the Humanities (DSH), currently under peer review.

The pipeline

  1. Clean and translateRemove markup from the raw articles and translate non-English texts to English.
  2. Split and preprocessFilter short documents, split the corpus into time periods, remove stopwords and lemmatise.
  3. EmbedRepresent every document as a vector with a long-context sentence-embedding model (GTE or Jina).
  4. Static topic modelFit BERTopic once on all documents: UMAP, HDBSCAN and c-TF-IDF, with KeyBERT-inspired topic words.
  5. Topics over timeGroup the documents by year and compute how frequent each topic is in each year.
  6. CompareScore BERTopic against LDA and NMF on topic coherence, topic diversity and runtime.

Worked example on a synthetic dataset

The newspaper corpus used in the paper is copyrighted, so neither the articles nor results derived from them can be shown here. The example below runs steps 2 to 5 on a synthetic dataset that ships with the repository.

About the example data. The 2,880 articles are invented. They are generated from sentence templates, with fictional places, people and events, and dated 1955 to 2018. Each article belongs to one of nine themes whose share changes over the years. Template-based text is far easier to separate than real newspaper text, so this example shows how the workflow runs and what its outputs look like. It is not evidence of how well the method performs on real archives.

Everything shown here is produced by example/bertopic_example.ipynb.

Following particular events

A sudden rise of one topic usually points to an event that was widely reported. The synthetic data contains three kinds of invented events: fuel shortages, floods and an influenza wave. Each chart below follows the topic of one event over the years. Labelled points are years in which the topic's share of the articles is at least twice its usual share.

All nine years are ones in which an event was built into the data. The same rule also flags 1981 and 1999 for the health topic, where no event was built in: with only 45 articles per year, chance alone can double a topic's share. A peak is a reason to read the documents behind it, not proof of an event.

Use it on your own data

Install the dependencies and run the example first:

git clone https://github.com/KeerthanaMurugaraj/Automating-Historical-Insight-Extraction-from-Large-Scale-Newspaper-Archives-via-NTM.git
cd Automating-Historical-Insight-Extraction-from-Large-Scale-Newspaper-Archives-via-NTM

conda create -n topic_modeling python=3.10
conda activate topic_modeling
pip install -r requirements.txt

cd example
python generate_dummy_dataset.py      # optional: the dataset is already included
jupyter notebook bertopic_example.ipynb

To apply the pipeline to another collection, provide a table with one document per row and at least these columns:

ColumnContent
uidA unique identifier for the document
contentThe text of the document
yearThe publication year, used for the topics-over-time analysis

Then adjust two things in the notebook: the path to your file, and min_cluster_size, which controls how fine-grained the topics are. For a large corpus, start from the BERTopic defaults. The full notebooks for each step, including the comparison with LDA and NMF, are described in the README.
